# TACZ Long Range Sniping

Minecraft 1.21.1 / NeoForge 21.1.248 / Java 21.

TACZ 的远距离狙击扩展项目，计划提供开镜实体同步、服务端碰撞快照和远程弹道，并兼容 NeoVoxy 远景显示。
当前已完成配置与 TACZ 接口层、弹道接管、内存碰撞快照、跨卸载区域弹道，以及合规开镜时的实体订阅、远距离绘制与受预算限制的远端区域模拟。
远端弹道默认开启，由服务端调度器推进符合条件的普通动能弹，利用完整快照穿过已卸载区域，命中另一端真实存在的实体。
快照、开镜实体显示与远端区域模拟默认开启。瞄准已知目标后可临时加载目标附近，恢复存档实体及真实 AI。
NeoVoxy 仍为可选依赖，本阶段不调用其私有渲染接口。

## 配置与白名单

启动世界／服务端后生成 `config/tacz_long_range_sniping-server.toml`。
NeoForge 也支持在存档的 `serverconfig/` 下放置同名文件覆盖全局配置。
配置类型为 SERVER，由服务端决定，并通过 NeoForge 同步给客户端；客户端本地配置不能扩大服务器授权。
本模组监听配置加载、重载和卸载事件，每次替换完整的不可变配置快照。
修改运行中的服务端文件可触发 NeoForge 重载；已连接客户端需要重新连接以确保收到最新配置。

```toml
[eligibility]
enabled = true
guns = ["tacz:ai_awp", "tacz:m95", "tacz:m700", "tacz:m107", "tacz:kar98", "tacz:springfield1873"]
scopeRules = [
  "tacz:scope_mk5hd|5,25,1.25|25",
  "tacz:scope_vudu|6.5,1.35|6.5",
  "tacz:scope_lpvo_1_6|6.25,1.25|6.25",
  "tacz:scope_standard_8x|4.5,10|10",
  "tacz:scope_1873_6x|6|6"
]

[limits]
maxDistance = 1024
maxTrackedEntities = 32
snapshotMemoryMiB = 128

[ballistics]
enabled = true
maxDistance = 0 # 跟随 limits.maxDistance
maxActiveBullets = 128
maxFlightTicks = 600
extendLifetime = true

[snapshots]
enabled = true
blocksPerTick = 4096
sectionsPerTick = 16
maxMillisPerTick = 2.0
refreshDelayTicks = 5
maxPendingSections = 8192
maxTrackedChunks = 8192

[scopeRendering]
enabled = true
intervalTicks = 4
maxCandidates = 256
maxTraceCells = 65536

[diagnostics]
enabled = false
```

每条瞄准镜规则是 `配件ID|完整有序倍率表|允许的倍率`。例如 `tacz:scope_mk5hd|5,25,1.25|25`
表示该镜有 5×、25×、1.25× 三档，仅 25× 合规。可写 `|5,25` 允许多档；倍率不要求为整数。
完整倍率表不能省略低倍率档位，也不能重排：TACZ 使用 `ZoomNumber % 档位数量` 选档。
倍率属于瞄准镜配件规则，同一瞄准镜规则适用于所有白名单枪械。

判定必须同时满足：主手枪械 ID 在白名单、实际安装的瞄准镜 ID 在白名单、当前档位倍率被允许、玩家正在开镜且存活并非旁观者。
还会确认服务端存在相应枪械／瞄准镜数据。此阶段仅支持安装在 SCOPE 槽的瞄准镜，不支持枪械内置光学瞄具。
空白名单拒绝全部；重复 ID、非法资源 ID、非正数或非有限倍率、允许倍率不属于档位表等规则错误会禁用资格判定并记录原因。
缺失配置键或 TOML 基本类型错误由 NeoForge 自身的配置修复机制处理。

默认枪械是当前依赖内置枪包的六种 `sniper`。枪械白名单不会自动允许新枪包的所有狙击枪。
白名单不改变 TACZ 的配件安装限制；例如 KAR98 获准并不代表它能安装上述每一种镜。
默认排除 4.25× 的专用镜；`scope_standard_8x` 在此 TACZ 版本中实际引用 `scope_scout_display`，
其倍率是 4.5×／10×，因此按 10× 配置，不能由物品名称推算。

服务端枪包数据没有客户端 display 的完整倍率数组，因此管理员需让规则与玩家枪包保持一致。
`TaczClientBridge.evaluateForDisplay` 为后续客户端功能提供倍率表一致性检查接口；它当前尚未接入 HUD，也不是服务端的授权凭据。
新增／修改枪包倍率时必须同步修改规则，并让客户端重新连接。

`limits.maxDistance` 同时约束显示、目标定位和弹道距离。`ballistics.maxDistance = 0` 跟随该值；正值只能进一步缩小弹道上限。
`limits.snapshotMemoryMiB` 限制全服已完成快照的估算内存，默认为 128 MiB。
`limits.maxTrackedEntities` 限制每名开镜玩家额外选择的实体数量，默认 32；`limits.maxDistance` 同时限制显示距离。
显示开关与弹道接管开关独立，可通过 `ballistics.enabled = false` 单独关闭新子弹的接管。

升级说明：原 `[prototype]` 配置节已替换为 `[ballistics]`，首次启动时 NeoForge 会补齐新节。
旧节的关闭开关和 128 格原型上限不再生效；曾自定义该节的管理员需将所需配置转移到新节，其他配置保留。

## 开镜实体订阅与显示

`scopeRendering.enabled = true` 时，只有枪械、安装的镜、当前倍率和开镜状态均通过原有资格判定，才启用额外订阅。
客户端还检查枪包实际倍率表与服务器配置一致。实体不再按 ID、继承关系或 Boss 标签设置白名单／黑名单：
普通生物、玩家、Boss、盔甲架、物品展示框、展示实体及掉落物都可进入候选。
旧配置的 `players` 与 `excludedClasses` 不再使用；枪械、瞄准镜、倍率的白名单仍保留。
隐身于观察者的实体、旁观者及服务端禁止向该玩家广播的实体仍不额外显示。

这里的“展示实体”包括原版 `item_display`／`block_display`／`text_display`。
箱子、告示牌等 `BlockEntity` 属于地形数据：它们会随活动区块运行，但尚不单独同步其远端专用渲染数据。
普通实体复用原生渲染器；依赖完整客户端地形或特殊客户端 tick 的第三方渲染器仍需单独兼容。

服务端每 4 tick 刷新一次候选目标，使用玩家自身同步的朝向，扫描瞄准附近的窄锥体。
半角按 `35° / 倍率` 计算并限制在 0.5°–6°，实体包围盒与锥体相交时也可入选。
优先选择接近准星方向的目标，再按距离和实体 ID 排序。每次每名玩家最多检查 256 个候选实体和 65536 个不同碰撞单元。
多个目标共用本轮视线读取缓存；预算耗尽的目标暂不订阅，不会继续无限查询。

目标头部或身体中心需要存在一条已知且无碰撞阻挡的视线；沿途使用当前区块或完整快照，缺失、淘汰、保守形状阻挡均拒绝。
这延续了第四步的一格邻域保守检查，墙角和复杂方块附近可能少显示目标。
实体筛选本身只查询服务端当前可访问的实体索引；下述区域管理器负责恢复远端目标。
关闭 `activity.enabled` 后仍可订阅服务端现有实体，但不会加载已卸载实体或恢复远端 AI。

通过筛选的实体加入现有原版实体追踪器的观察者集合，复用原版生成、外观、装备、状态、移动和移除消息。
额外发送有数量上限的身份、显示位置和光照数据，以便客户端没有目标区块时仍能插值显示；不发送整块地形。
正常追踪和开镜追踪共用同一实体身份，进入普通视距时不生成第二个模型。
收镜、切换到不合规倍率、切枪、禁用功能、死亡或切换维度后撤销额外授权；服务端每 tick 检查资格。
如果原版仍应追踪该目标，撤销额外授权时保留原版观察关系。

客户端仅补绘原版因距离或未编译地形区块段而跳过的已授权实体，保留视锥与深度测试。
在没有本地目标区块时，只推进显示位置和基础动画，不执行生物 AI、碰撞或服务端伤害。
开镜期间扩大投影远裁剪范围，并仅在补绘批次中使用远距离雾和服务端光照；收镜恢复普通路径。
同一帧中原版已经绘制的实体不会再次补绘。网络停止更新时显示授权自动超时。

NeoVoxy 的 LOD 地形可与这些实体一起显示，但本阶段尚未验证特定 NeoVoxy／Sodium／光影组合的深度缓冲兼容性。
没有远景模组时，原版视距外缺少背景地形是预期现象；服务端视线检查仍负责阻止未知区域或已知山体后的目标订阅。

## 开镜远端区域模拟

`[activity].enabled = true` 默认开启，与弹道接管开关独立。所有加载均由服务端验证装备、倍率、开镜状态、距离和视线后决定。

1. 用当前地形／完整快照沿准星寻找第一个阻挡位置，或准星实际穿过的已可见实体；未知区域、预算耗尽、全程空气均不能提供地形加载目标。
2. 在同一目标区块稳定瞄准至少 8 tick 后申请区域。目标留在自己现有活动核心内时复用区域。
3. 核心及周边 FULL 区块和一圈光照加载邻域必须在本次服务端会话中已完成加载，或当前真实可用。
   使用最多 65536 个坐标的内存记录作非加载检查，不读磁盘来探路；记录淘汰／重启后可能保守拒绝。
4. 添加原生区块票据，等待核心进入实体更新状态；不调用同步 `getChunk`／阻塞等待。
   从存档恢复的生物随后进入正常世界更新与实体订阅。沿途区块仍可保持卸载。
5. 区域中的全部实体／方块实体正常运行，核心也启用 NeoForge 强制随机刻。
   对核心中的 Mob 临时跳过距离引起的消失，并解除闲逛目标的闲置计数限制；保留和平难度、NoAI、第三方事件及持久化标记。
6. 收镜或转移后默认保留 40 tick 宽限；若有已接管子弹飞向该区域，则继续保留到飞行结束或飞行时间上限。
   只有观察者宽限与在途保留都结束，才移除本模组票据；实际保存和卸载由 Minecraft 调度。
   退出、切换维度、关闭功能、修改活动配置、世界卸载会清理对应申请／票据。

| 配置键 | 默认值 | 含义 |
|---|---:|---|
| `radius` | 1 | 3×3 实体更新核心；FULL 票据覆盖 7×7，即 49 区块 |
| `stableTicks` | 8 | 稳定瞄准等待，正常 20 TPS 时约 0.4 秒 |
| `retentionTicks` | 40 | 移开／收镜后的保留时间，正常 20 TPS 时约 2 秒 |
| `maxFullChunks` | 196 | 全服 FULL 票据覆盖的并集预算，包含正在加载、宽限中及被在途子弹保留的区域 |
| `maxDependencyChunks` | 4096 | 包含更外围低状态依赖的保守坐标预算，也包含 FULL 区块 |
| `maxRegions` | 4 | 全服区域数量上限；每人同时保留最多两个区域（含旧区域宽限及在途保留） |
| `startsPerSecond` | 2 | 任意连续 20 个服务端 tick 内最多新建两个区域 |
| `loadTimeoutTicks` | 100 | 核心未就绪的超时，移除票据并释放预算 |
| `maxQueriesPerTick` | 2 | 全服每 tick 额外准星定位查询上限；每条查询仍受碰撞单元预算限制 |

多人瞄准同一中心的区域共享租期；相邻区域重叠的核心票据引用计数，FULL／依赖预算按坐标并集计算。
已经被其他玩家或模组加载的目标也使用本模组独立的票据保留，并照常计入预算，不重复创建世界区块或实体。
只添加／移除本模组自己的票据，不修改强加载列表，不强制卸载区块；其他票据保留时区块继续运行，其他票据撤销也不影响本模组的有效保留。
超出预算时不启动新区域，继续保留可正常订阅的现有实体。多人争用时可能增加响应时间。
预算限制的是本模组申请的覆盖，不是整个服务器的实际驻留区块或硬性毫秒上限；
原版卸载、其他加载器以及第三方 AI 自行访问世界产生的额外开销不由此预算控制。

AI 的寻路、捕猎、吃草等遵循各生物原本行为、周围地形、猎物及游戏规则。
活动区外的猎物可能未加载，走出核心的生物可能暂停；不无限追随它们扩大区域。
碰撞快照仍只用于远端视线／弹道，不代替真实 AI 世界，Voxy 仍为可选远景显示模组。

## 内存碰撞快照与覆盖索引

`[snapshots].enabled = true` 默认开启自然加载区块的快照采集，与弹道接管开关相互独立。
采集器自身不主动加载区块，也不要求安装 NeoVoxy。区域管理器恢复的真实区块同样会经过快照采集与失效流程。

每个缓存地址为 `维度 ID + 区块段 X/Y/Z`，一个区块段为 16×16×16 格。Y 是世界区块段坐标，包含负数。
覆盖索引与快照共用生命周期，提供三种状态：

| 状态 | 含义 |
|---|---|
| `UNKNOWN` | 未采集、正在采集、被修改而失效、被淘汰，或缓存已关闭 |
| `KNOWN_AIR` | 完整采集且全部等同于无水的空碰撞空间；真正全空气的区块段可走快速路径 |
| `KNOWN` | 已完成采集，包含其他碰撞／介质数据；不表示地形一定可以穿过 |

`coverage`、`find` 和 `cell` 查询只访问内存；缺失时返回未知／空结果，不请求区块、不安排采集。
只有完整的 4096 格采集结果能够发布。按多个 tick 分批采集时，半成品始终不在覆盖索引中。
快照有单调递增的发布版本和采集完成时的服务器采集 tick，已返回的快照对象不会被原地修改。

采集与刷新流程：

- 区块自然加载时登记坐标并安排各区块段。加载事件中不读取地形；真正采集延迟到服务器 tick，使用 `getChunkNow` 非加载查询。
- 每次只保留一个正在生成的快照。一次采集调用结束后，不在队列或半成品中保留 `LevelChunk`、`LevelChunkSection`、实体或方块实体引用。
- `LevelChunk.setBlockState` 成功修改方块后，立即使所属区块段的旧快照失效，并合并刷新请求。
  若该段正在采集，丢弃半成品后重做，避免发布修改前后混合的数据。新修改请求默认延迟 5 tick；已有待办可能更早处理。
- 区块卸载时删除其待办与半成品，保留已经完成的快照。区块再次加载时使旧快照失效，重新采集。
- 维度卸载、退出世界或停服时清理对应数据。本阶段不写入磁盘，重启后需要重新采集。
- 关闭缓存后查询立即返回未知，并在服务器 tick 清空数据；保留有上限的自然加载坐标索引，以便重新开启后逐步恢复。

快照以形状调色板和压缩索引保存碰撞数据，统一形状的区块段无需保存逐格索引。
数据仅包含不可变数值，不持有 Minecraft 方块状态或世界对象：

- 支持原版非动态、无方块实体的预计算碰撞形状；半砖、楼梯、栅栏等保留实际碰撞盒。原版无碰撞方块记录为空碰撞。
- 记录是否含水，供跨卸载区域弹道近似计算水中阻力和重力。
- 模组方块、依赖实体状态的动态形状、带方块实体的形状，以及超出当前表示范围的复杂形状，记录 `CONSERVATIVE` 保守阻挡标记。
  不尝试运行它们的自定义世界查询，也不当成空气处理。
- 每种形状最多保存 16 个碰撞盒，坐标为方块局部坐标，允许范围为 `[-1, 2]`。
  碰撞盒可能跨出本方块（例如栅栏高于一格）；弹道追踪同时检查周围一格单元。

原版放置、破坏、流体、活塞与命令通过上述修改入口时均会触发失效。
第三方工具若绕过 `LevelChunk.setBlockState` 直接改写区块段底层容器，需要另行适配其修改通知。
缓存采集的是方块碰撞几何；TACZ 对特殊方块的额外穿透规则、命中副作用以及实体碰撞不包含在本快照层中。

资源预算均在服务端执行：

- 全服每 tick 最多采集 4096 格、完成 16 个区块段，另设 2 ms 软时间预算；全空气快速路径仍消耗一次工作额度。
  时间预算每 64 格检查一次，不能保证每个 tick 的耗时严格低于 2 ms。
- 完成的快照共享 `limits.snapshotMemoryMiB` 预算，采用 LRU 淘汰；被淘汰的段立即成为未知。
  这是对象大小的保守估算，不是 JVM 堆使用量的精确计量。队列、坐标索引和单个构建器另外受数量上限约束。
- 待办最多 8192 段，同一段的重复请求合并。队列满时暂时省略新请求，保持未知；轮询已登记区块时会重试。
- 最多登记 8192 个自然加载区块坐标，溢出时忘记最早的登记。遗漏坐标可在重新加载或正常方块修改后重新登记。
  队列补充每 tick 轮询一个已登记区块，不会为了补齐缓存加载真实区块。

## 弹道接管与跨卸载区域射击

`[ballistics].enabled = true` 默认开启。`maxDistance = 0` 跟随 `limits.maxDistance`，默认 1024 格；
正值可单独限制弹道距离（最多 16384 格，且不超过全局上限）。距离按累计飞行路径长度计算。

原先的默认关闭开关、128 格上限，以及 TACZ 原生子弹寿命都可能造成远端无法命中。
例如当前依赖默认枪包中的 AWP 子弹寿命为 0.9 秒（18 tick），即使目标区块正常模拟，也可能在途中消失；
原生实体子弹还可能在沿途区块停止模拟时暂停。接管后子弹独立推进，不需要沿途区块进入实体更新状态。
`extendLifetime = true` 仅对成功接管的弹延长寿命，最多运行 `maxFlightTicks`（默认 600 tick，正常 20 TPS 时为 30 秒）。
枪口速度、阻力、下坠、穿透及伤害衰减保持原值；距离上限并不保证能飞到该距离，需要考虑下坠、阻挡和覆盖。
设为 `false` 可恢复原始寿命约束。未接管的子弹不修改寿命。

接管发生在原子弹完成初始化、即将加入世界时：

1. 复用第一步的枪械、瞄准镜、倍率与开镜资格判定。
2. 仅接受标准 `EntityKineticBullet` 普通动能弹。爆炸、实体燃烧、方块燃烧及自定义子弹子类继续使用原 TACZ 路径。
3. 调度器获得子弹所有权后取消原实体生成。这份未注册到世界的 TACZ 子弹仅由调度器推进，不再由世界实体列表重复推进。
4. 如果完整扫掠包围盒及两格周边范围都已加载，继续复用 TACZ 原生 `tick()`，保留本地飞行、流体及方块命中行为。
5. 若经过卸载区域，或需要在本 tick 内截断距离，改用不调用 `Entity`／`Projectile` 基础 tick 的快照路径。
   此后该发子弹保持这条路径，避免恢复陈旧的基础实体流体／传送门状态。
   NeoForge 的 tick 前后事件仍然保留；前置事件修改后的真实位置和速度用于当次检测。

快照路径每 tick 检测本次实际位移线段，包含此前重力、阻力和开火散布形成的偏移，不依赖开镜时的一条静态直线：

- 当前区块存在时直接读取其现有区块段；当前地形优先于历史快照，且不必等待缓存重新采集。
- 当前区块已卸载时，仅使用完整快照；未采集、半成品、失效、淘汰或关闭缓存均视为未知。
- 使用逐格 DDA 与具体碰撞盒求交，检查线段周围一格，覆盖栅栏等伸出方块的形状。
  周围一格也必须已知，因此在覆盖边缘可能提前约一格停弹。`CONSERVATIVE` 单元及其邻近路径保守阻挡。
- 遇到墙体或未知数据时保留已知前缀，在首次边界前停止；不会因为远端有一个已加载目标就跳过中间缺口。
  累计距离上限在最后一段精确截断，不再整 tick 提前停弹。
- 在安全前缀内按命中距离排序真实服务端实体，复用 TACZ 碰撞盒／爆头判断、原子弹伤害与命中事件，逐次消耗原生穿透数。
  伤害事件取消仍有效，不创建历史实体或再次扣除弹药。其他玩家只要真实存在且可被服务端查询，也走同一实体路径。
- 使用原 TACZ 的“位移、阻力、重力、寿命”顺序及浮点运算精度；快照含水格按水中系数计算。
  快照没有流体高度／流向，部分浸水和流体推力并不保证与原生路径完全一致。
- 所有地形读取仅用 `getChunkNow` 或内存快照，缺失查询不排队、不读取磁盘、不请求区块票据，也不新增地形同步消息。
  短暂的区块段读取器只存在于本次计算，不会跨 tick 保持区块引用。

资源限制与生命周期：

- 每 tick 位移长度最多 256 格，DDA 最多访问 1024 个路径单元，避免异常枪包速度产生无界查询。
  超出该速度或非有限坐标会终止已接管子弹；这与可跨多个 tick 飞行的总距离上限不同。
- 默认每个维度最多接管 128 发同时飞行的子弹，允许配置 1–1024 发。容量已满时新子弹保留原 TACZ 行为；
  这些未接管子弹不受本模组距离／覆盖检查约束。
- 默认飞行硬上限为 600 tick。收镜、切枪和关闭新接管开关不会撤销已经接管的子弹。
  射手死亡、离开世界或切换维度时清理其弹道；维度卸载、停服时释放持有的子弹。飞行状态不保存到存档。
- 如其他生成事件监听器撤销了取消标记、让原实体最终成功注册，调度器会放弃所有权并恢复其原始寿命；若第三方另行修改寿命则保留该修改，避免双重推进。
- 尚无被接管子弹的普通曳光显示；远端目标仅在开镜订阅规则允许时显示。
  本地原生路径保留 TACZ 方块命中反馈；快照路径撞墙只停止子弹，不调用可能读取／修改卸载地形的方块命中事件或生成弹孔。
- 快照路径使用保守碰撞几何，暂未复刻 TACZ 特殊方块穿透标签／配置和自定义方块行为；某些原生可穿过的方块可能阻挡。
  区块在卸载期间的地形仍以最后完整快照为准，重新加载后恢复当前数据优先。

开火时，接管子弹会保留射手已获批、与发射方向水平路径相交的目标区域；保留整列高度以兼容抬枪补偿下坠。
不会为在途子弹新建区域、加载走廊或绕过预算。关镜只撤销额外显示，仍在飞行的子弹可以命中被保留的真实实体。
命中终结、撞墙、未知覆盖、射程或寿命到限都会释放该发子弹的保留；多发共享区域时，其他有效保留继续生效。
这些区域一直占用全服 FULL／依赖／区域预算及每人两区域上限，不能通过连续开镜射击积累无限加载区块。
飞行超时还为保留设置兜底期限；暂停游戏不会单独消耗保留期限。
管理员关闭区域功能、变更活动配置、世界卸载等管理操作仍可主动清理区域；已走出核心的目标也不保证继续模拟。

弹道与实体筛选不主动加载沿途区块；开镜区域管理器单独负责有预算的目标加载。快照不持久化，也不依赖 NeoVoxy。
已卸载地形以历史快照为准，不能保证反映第三方绕过通知的修改；未知或被淘汰的覆盖始终截断弹道，不为补齐它临时加载区块。
原生实体伤害和 NeoForge 事件仍允许第三方回调；本扩展不替其他模组约束其任意世界访问。
快照表示服务器曾完整采集该区域，不是每名玩家各自曾看过该区域的证明；当前没有按玩家保存探索历史。

## 调试与接口边界

- 管理员执行 `/taczlrs cache`（权限等级 2），查看全服快照数量、待办、估算内存、淘汰／丢弃请求次数及上一 tick 工作量，
  同时查看执行位置所在区块段的覆盖状态、版本和保守阻挡格数。命令本身不会触发采集或区块加载。
- 游戏内执行 `/taczlrs status`，查看自己的枪械、瞄准镜、当前档位、倍率及拒绝原因，无需 OP。
  同时显示弹道开关、距离上限、当前维度的活动／累计接管／未知区域终止／距离终止计数，
  以及延长寿命开关、飞行时间上限、寿命／超时终止、快照阻挡、最后终止原因与最后接管结果。活动区域状态包含在途保留数（按区域分别计数）。
  也显示开镜实体订阅开关、数量上限、当前订阅数和刷新间隔。
- 开启 `diagnostics.enabled` 后，服务端日志在资格变化时输出状态，在合规子弹生成时输出参数与接管结果，并记录弹道终止原因。
  订阅集合变化也会记录。输入聊天命令通常会收镜，观察真实开镜与变倍状态时应使用这个日志开关。
- `TaczBridge.evaluate` 在调用时重新读取装备和状态；服务端使用射手即时开镜状态，避免同步标记延迟。
- `TaczBridge.inspectNewBullet` 在 TACZ 初始化子弹之后读取实际位置、速度、寿命、重力、阻力、穿透数、有效射程、爆头倍率、穿甲比例及爆炸／燃烧标记。
  有效射程是 TACZ 的伤害参数，不等于子弹最大飞行距离。接管时只按配置延长寿命，不重新计算伤害衰减等参数。
- `TaczShotObservedEvent` 是服务端的不可取消观察事件，包含原始子弹和不可变的开火时快照，在弹道接管判定前发布。
  已加载存档实体、客户端实体、不合规装备以及枪械 ID 不匹配的子弹不会发布此事件。
- 私有参数通过 Mixin Accessor 获取；快照路径另外使用原生实体命中 Invoker，并递减子弹剩余穿透数。
  接口按固定的 TACZ `1.1.8-hotfix-r6` 验证；升级 TACZ 后需重新运行测试。

## 验证

`build` 包含 JUnit 测试，覆盖联合白名单、切枪／收镜／变倍、循环变倍序号、非法配置与小数倍率，
并直接读取依赖 JAR 核对默认枪械类别和瞄准镜引用的真实倍率表。
`runGameTestServer` 在 `build/gametest` 下启动无 NeoVoxy 的专用测试服务端，验证配置加载、实际 TACZ 装备状态、
即时开镜判定及子弹参数 Mixin。第二步增加原生与接管弹道对照：空气／水中轨迹与寿命、身体／头部伤害、穿透、墙体遮挡、
未知中间区块不加载、距离与容量限制、特殊弹药回退、伤害事件取消、实际生成事件接管、唯一推进及生命周期清理。
测试中部分寿命／重力／阻力／穿透／特殊弹药字段由测试夹具设定，以隔离验证对应行为，生产代码仅对成功接管的子弹按配置延长寿命。
第三步增加快照发布原子性、修改期间重建、负坐标／维度隔离、预算／淘汰、真实半砖／楼梯／栅栏形状、
修改 Mixin、无副作用查询及自然卸载后仍可查询快照的测试。
第四步增加已知／未知路径、负坐标和边界、斜线、细小与跨格形状、重力偏移、异常输入、精确距离截断，
以及快照路径与原生身体／头部伤害、穿透事件的对照测试。
实际服务端测试先采集一段走廊、等待中间三个区块自然卸载，再只开放首尾区块，验证远端命中、缓存墙体、
多 tick 飞行、伤害取消、当前地形优先、覆盖失效后截断，以及射击没有增加已加载区块或请求采集。
测试类和测试结构位于独立 `gameTest` 源集，不进入发布 JAR。
开镜功能验证实体类型不再受类别筛选、倍率撤销、原版观察者交接、墙体／未知区域／读取预算及网络消息边界。
远端模拟测试验证存档生物卸载后恢复、真实寻路与狼攻击猎物、敌对生物距离消失豁免、FULL 预算拒绝、多人共享区域与分别收镜、实际卸载。
新增测试验证短寿命弹延寿后的射程／时间硬上限、原生所有权恢复时还原寿命，以及真实远端目标区块在收镜超过宽限后仍被在途子弹保留并命中。
同一场景验证中间区块保持卸载、独立第三方票据的双向撤销互不影响、在预先加载的区域重新开镜不会重建实体。
`runClientScopeTest` 使用 `build/client-scope-test` 下新建的隔离单人存档，自动检查 6 区块视距外的真实实体订阅、服务端原生寻路移动、生物及掉落物补绘与收镜移除，
保存 `screenshots/scope-render.png`，成功后自动退出；测试过程自身会准备地形与目标，这不是生产订阅逻辑的区块加载行为。
多人网络环境、模组自定义生物渲染器以及 NeoVoxy／Sodium／光影组合仍需在对应整合包中验证。
