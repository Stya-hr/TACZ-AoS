# TACZ Long Range Sniping

Minecraft 1.21.1 / NeoForge 21.1.248 / Java 21.

TACZ 的远距离狙击扩展项目，计划提供开镜实体同步、服务端碰撞快照和远程弹道，并兼容 NeoVoxy 远景显示。
当前已完成配置与 TACZ 接口层、弹道接管、碰撞快照及磁盘持久化、跨卸载区域弹道，以及合规开镜时的实体订阅、远距离绘制与受预算限制的远端区域模拟。
远端弹道默认开启，由服务端调度器推进符合条件的普通动能弹，利用完整快照穿过已卸载区域，命中另一端真实存在的实体。
快照、开镜实体显示与远端区域模拟默认开启。瞄准已知目标后可临时加载目标附近，恢复存档实体及真实 AI。
NeoVoxy 仍为可选依赖，本阶段不调用其私有渲染接口。

开镜加载、测距与远端弹道接管的使用条件：玩家位置到任意完整测距仪的两格占位包围盒的最短直线距离不超过 3 blocks（包含边界）。
枪械 ID 和安装的瞄准镜 ID 必须在白名单内，正在瞄准时所有倍率均可用。
离开范围或拆掉最后一台附近测距仪后，停止测距、额外实体显示和本模组在途弹道，撤销该玩家的远端区域保留；
其他玩家的共享区域和原版／第三方加载票据不受影响。仅收镜但仍在测距仪旁时，已发射子弹及其目标区域仍保留至飞行结束。
枪械物理覆盖独立于上述条件：默认五把狙击枪在所有射击场景使用配置参数，详见下文 `gunOverrides`。
距离查询每玩家每 tick 缓存附近方块候选，只读已加载区块；同 tick 的移动重新核对精确距离，放置／拆除立即使候选缓存失效。

## 配置与白名单

启动世界／服务端后生成 `config/tacz_long_range_sniping-server.toml`。
NeoForge 也支持在存档的 `serverconfig/` 下放置同名文件覆盖全局配置。
配置类型为 SERVER，由服务端决定，并通过 NeoForge 同步给客户端；客户端本地配置不能扩大服务器授权。
本模组监听配置加载、重载和卸载事件，每次替换完整的不可变配置快照。
修改运行中的服务端文件可触发 NeoForge 重载；已连接客户端需要重新连接以确保收到最新配置。

```toml
[eligibility]
enabled = true
guns = ["tacz:ai_awp", "tacz:m95", "tacz:m700", "tacz:m107", "tacz:kar98", "tacz:springfield1873"]
scopeRules = [
  "tacz:scope_mk5hd|5,25,1.25",
  "tacz:scope_vudu|6.5,1.35",
  "tacz:scope_lpvo_1_6|6.25,1.25",
  "tacz:scope_standard_8x|4.5,10",
  "tacz:scope_1873_6x|6",
  "tacz:scope_98k|4.25"
]

[limits]
maxDistance = 1024
maxTrackedEntities = 32
snapshotMemoryMiB = 128

[ballistics]
enabled = true
maxDistance = 0 # 跟随 limits.maxDistance
maxActiveBullets = 128
maxFlightTicks = 600
extendLifetime = true

[snapshots]
enabled = true
blocksPerTick = 4096
sectionsPerTick = 16
maxMillisPerTick = 2.0
refreshDelayTicks = 5
maxPendingSections = 8192
maxTrackedChunks = 8192

[scopeRendering]
enabled = true
intervalTicks = 4
maxCandidates = 256
maxTraceCells = 65536

[diagnostics]
enabled = false
```

每条瞄准镜规则可以只写 `配件ID`，也可写 `配件ID|完整有序倍率表`，所有倍率均允许。
倍率表仅用于服务端尚未收到实际客户端视野时的估算，不再作为授权门槛。
只写默认瞄具 ID 时使用内置倍率布局；其他 ID 缺省按 1× 保守估算，收到客户端实际投影后更新。
旧的三字段写法仍可读取，但第三段“允许的倍率”已忽略，无需删除旧配置即可启用全部倍率。

判定必须同时满足：附近 3 格有完整测距仪、主手枪械 ID 在白名单、实际安装的瞄准镜 ID 在白名单、玩家正在开镜且存活并非旁观者。
还会确认服务端存在相应枪械／瞄准镜数据。此阶段仅支持安装在 SCOPE 槽的瞄准镜，不支持枪械内置光学瞄具。
空白名单拒绝全部；重复 ID、非法资源 ID、非正数或非有限倍率布局等规则错误会禁用资格判定并记录原因。
缺失配置键或 TOML 基本类型错误由 NeoForge 自身的配置修复机制处理。

默认枪械是当前依赖内置枪包的六种 `sniper`。枪械白名单不会自动允许新枪包的所有狙击枪。
白名单不改变 TACZ 的配件安装限制；例如 KAR98 获准并不代表它能安装上述每一种镜。
默认包含 KAR98 的 4.25× 专用镜；`scope_standard_8x` 在此 TACZ 版本中实际引用 `scope_scout_display`，
其倍率是 4.5×／10×，不能由物品名称推算；两档均可用。

服务端枪包数据没有客户端 display 的完整倍率数组；可选倍率表建议与枪包一致，以改善首次视野估算。
客户端直接读取实际瞄具的倍率和视图类型，资源包与可选服务端布局不同不会禁止显示，也不会扩大枪械／瞄具 ID 授权。

`limits.maxDistance` 同时约束显示、目标定位和弹道距离。`ballistics.maxDistance = 0` 跟随该值；正值只能进一步缩小弹道上限。
`limits.snapshotMemoryMiB` 限制全服已完成快照的估算内存，默认为 128 MiB。
`limits.maxTrackedEntities` 限制每名开镜玩家额外选择的实体数量，默认 32；`limits.maxDistance` 同时限制显示距离。
显示开关与弹道接管开关独立，可通过 `ballistics.enabled = false` 单独关闭新子弹的接管。

升级说明：原 `[prototype]` 配置节已替换为 `[ballistics]`，首次启动时 NeoForge 会补齐新节。
旧节的关闭开关和 128 格原型上限不再生效；曾自定义该节的管理员需将所需配置转移到新节，其他配置保留。

## 全局枪械参数配置

使用已有 `config/tacz_long_range_sniping-server.toml` 的 `[gunOverrides]` 节；若存档 `serverconfig/` 存在同名配置，应修改实际生效的存档文件。
这里选择配置文件，便于服主直接按枪 ID 编辑少量数值，并复用 NeoForge 的服务端配置管理；无需改 TACZ JAR、解包枪包或维护数据包优先级。
建议退出存档／停止服务器后修改，再重新进入／启动，不使用 `/reload` 管理这些设置。

```toml
[gunOverrides]
enabled = true
entries = [
  "tacz:ai_awp|speed=905|gravity=9.80665|friction=0.023833333",
  "tacz:m95|speed=858|gravity=9.80665|friction=0.014333333",
  "tacz:m107|speed=858|gravity=9.80665|friction=0.014333333",
  "tacz:m700|speed=822.96|gravity=9.80665|friction=0.030666667",
  "tacz:kar98|speed=780|gravity=9.80665|friction=0.0275"
]
```

向列表追加 `"your_pack:rifle_id|speed=800|gravity=9.80665|friction=0.02"` 即可覆盖第三方 TACZ 枪包中对应 ID 的枪。
也可只写 `"tacz:ak47|speed=715"`：只覆盖初速，重力与阻力继续使用该枪原值；不需要把它加入狙击白名单。
ID 是枪包内枪械 ID（例如 `tacz:ai_awp`），不是通用物品 ID `tacz:modern_kinetic_gun`。
未安装的枪 ID 不会导致加载失败，等对应枪包安装后再匹配；拼错但语法合法的 ID 不会匹配任何枪。

| 字段 | 单位与含义 | 允许范围 |
| --- | --- | --- |
| `speed` | 出膛速度 blocks/s，1 block 当作 1 米；内部除以 20。是最终值，覆盖 TACZ 全局速度倍率和配件初速变化 | 大于 0，不超过 5120 |
| `gravity` | 重力加速度 m/s²；内部除以 400 | 0–400 |
| `friction` | 每 tick 损失的空气速度比例，例如 0.02 表示损失 2%；不是现实阻力系数 Cd | 大于等于 0，小于 1 |

字段省略则保留原值；删除一条枪械记录则恢复该枪的全部原值。`enabled = false` 或 `entries = []` 关闭全部物理覆盖，远端功能仍由各自配置控制。
同一枪 ID 只能出现一次，一行中每个字段也只能出现一次；最多 1024 个 ID。
非法数值、重复项或未知字段会拒绝整份覆盖列表并在日志记录错误，其他狙击功能继续按自己的配置运行。
每次发射只进行一次 ID 查询与少量字段赋值，不在飞行途中反复切换参数，也不修改 TACZ 的共享枪械数据或配件缓存。

## 开镜实体订阅与显示

`scopeRendering.enabled = true` 时，附近测距仪、枪械、安装的镜和开镜状态通过资格判定后启用额外订阅，各倍率均可用。
实体不再按 ID、继承关系或 Boss 标签设置白名单／黑名单：
普通生物、玩家、Boss、盔甲架、物品展示框、展示实体及掉落物都可进入候选。
旧配置的 `players` 与 `excludedClasses` 不再使用；枪械与瞄准镜 ID 的白名单仍保留。
隐身于观察者的实体、旁观者及服务端禁止向该玩家广播的实体仍不额外显示。

这里的“展示实体”包括原版 `item_display`／`block_display`／`text_display`。
箱子、告示牌等 `BlockEntity` 属于地形数据：它们会随活动区块运行，但尚不单独同步其远端专用渲染数据。
普通实体复用原生渲染器；依赖完整客户端地形或特殊客户端 tick 的第三方渲染器仍需单独兼容。

服务端每 4 tick 刷新一次候选目标，使用玩家自身同步的朝向，扫描瞄准附近的锥体。
客户端从实际世界投影计算包含整个窗口的对角半角，保守覆盖镜片，适配倍率、FOV 和窗口比例。
新目标的订阅宽度在此基础上增加 15%；已订阅目标到增加 35% 的更外圈才撤销，减少镜片边缘反复出现／消失。
扩展比例应用于锥体横向宽度（半角的正切），实体包围盒与锥体相交时也可入选。
客户端补绘使用实际画面视锥、投影裁剪和深度测试，不再用第二个狭窄准星锥体裁掉镜内目标。
视野变化最多每 10 tick 上报一次，稳定时每 40 tick 心跳；消息只包含维度、倍率和半角。
服务端重新验证开镜资格、维度，并限频；实际投影半角受 30° 硬上限限制，各倍率共用相同的实体与区域预算。
未收到提示或提示超过 100 tick 时，采用按倍率估算的保守默认视野。网络协议已更新，客户端和服务端需要同时更新本模组。
优先选择接近准星方向的目标，再按距离和实体 ID 排序。每次每名玩家最多检查 256 个候选实体和 65536 个不同碰撞单元。
多个目标共用本轮视线读取缓存；预算耗尽的目标暂不订阅，不会继续无限查询。
已订阅目标优先进入候选检查，但最终仍按准星接近程度排序，外围保留目标不能挤占更中央目标的名额。
原有每人实体上限、候选／碰撞查询预算和区域加载预算不变；实际同步和绘制的实体可能略增。
扩大订阅范围不会申请覆盖整个镜片的模拟区块，区域模拟由实际参数预测的首次弹着点决定。
因此尚未恢复的实体、未知地形、预算拥挤和快速甩镜／网络延迟仍可能造成晚出现，缓冲圈主要解决已有实体的角度裁剪边界。

目标头部或身体中心需要存在一条已知且无碰撞阻挡的视线；沿途使用当前区块或完整快照，缺失、淘汰、保守形状阻挡均拒绝。
这延续了第四步的一格邻域保守检查，墙角和复杂方块附近可能少显示目标。
实体筛选本身只查询服务端当前可访问的实体索引；下述区域管理器负责恢复远端目标。
关闭 `activity.enabled` 后仍可订阅服务端现有实体，但不会加载已卸载实体或恢复远端 AI。

通过筛选的实体加入现有原版实体追踪器的观察者集合，复用原版生成、外观、装备、状态、移动和移除消息。
额外发送有数量上限的身份、显示位置和光照数据，以便客户端没有目标区块时仍能插值显示；不发送整块地形。
正常追踪和开镜追踪共用同一实体身份，进入普通视距时不生成第二个模型。
离开测距仪、拆除测距仪、收镜、切枪、禁用功能、死亡或切换维度后撤销额外授权；服务端每 tick 检查资格。
如果原版仍应追踪该目标，撤销额外授权时保留原版观察关系。

客户端仅补绘原版因距离或未编译地形区块段而跳过的已授权实体，保留视锥与深度测试。
在没有本地目标区块时，只推进显示位置和基础动画，不执行生物 AI、碰撞或服务端伤害。
开镜期间扩大投影远裁剪范围，并仅在补绘批次中使用远距离雾和服务端光照；收镜后结束实体补绘；仍有在途尾迹时，远裁剪暂时保留到尾迹消散。
同一帧中原版已经绘制的实体不会再次补绘。网络停止更新时显示授权自动超时。

NeoVoxy 的 LOD 地形可与这些实体一起显示，但本阶段尚未验证特定 NeoVoxy／Sodium／光影组合的深度缓冲兼容性。
没有远景模组时，原版视距外缺少背景地形是预期现象；服务端视线检查仍负责阻止未知区域或已知山体后的目标订阅。

## 开镜远端区域模拟

`[activity].enabled = true` 默认开启，与弹道接管开关独立。所有加载均由服务端验证附近测距仪、装备、开镜状态、距离和预测弹道覆盖后决定。

1. 用当前狙击模式生效的初速、重力和阻力预测下坠轨迹，寻找曲线上的首次地形碰撞或已可见实体碰撞；未覆盖的枪械读取 TACZ 参数，原始寿命仍读取枪包数据。沿途只查询当前地形／完整快照；未知区域、预算耗尽、寿命耗尽、射程内全程空气均不能提供加载目标。
2. 初次满足开镜资格（包括保持开镜走入测距仪范围）立即测距、预测，并在预算允许时申请已知落点区域；无需重新开镜。
   随后的目标切换仍需在同一目标区块稳定至少 8 tick。目标留在自己现有活动核心内时复用区域；实际加载及实体同步异步完成。
3. 核心及周边 FULL 区块和一圈光照加载邻域必须有本次会话的加载记录、当前真实区块，或有效碰撞缓存证明曾经加载。
   使用有上限的会话记录及内存／磁盘缓存索引作非加载检查，不同步读盘探路；每个邻域区块分别检查，缺失时拒绝。
4. 添加原生区块票据，等待核心进入实体更新状态；不调用同步 `getChunk`／阻塞等待。
   从存档恢复的生物随后进入正常世界更新与实体订阅。沿途区块仍可保持卸载。
5. 区域中的全部实体／方块实体正常运行，核心也启用 NeoForge 强制随机刻。
   对核心中的 Mob 临时跳过距离引起的消失，并解除闲逛目标的闲置计数限制；保留和平难度、NoAI、第三方事件及持久化标记。
6. 在测距仪旁收镜或转移瞄准后默认保留 40 tick 宽限；若有已接管子弹飞向该区域，则继续保留到飞行结束或飞行时间上限。
   离开测距仪范围或移除最后一台附近设备时，下一服务器 tick 撤销该玩家的保留，不等待宽限；共享使用者单独核验。
   只有观察者宽限与在途保留都结束，才移除本模组票据；实际保存和卸载由 Minecraft 调度。
   退出、切换维度、关闭功能、修改活动配置、世界卸载会清理对应申请／票据。

| 配置键 | 默认值 | 含义 |
|---|---:|---|
| `radius` | 1 | 3×3 实体更新核心；FULL 票据覆盖 7×7，即 49 区块 |
| `stableTicks` | 8 | 稳定瞄准等待，正常 20 TPS 时约 0.4 秒 |
| `retentionTicks` | 40 | 移开／收镜后的保留时间，正常 20 TPS 时约 2 秒 |
| `maxFullChunks` | 196 | 全服 FULL 票据覆盖的并集预算，包含正在加载、宽限中及被在途子弹保留的区域 |
| `maxDependencyChunks` | 4096 | 包含更外围低状态依赖的保守坐标预算，也包含 FULL 区块 |
| `maxRegions` | 4 | 全服区域数量上限；每人同时保留最多两个区域（含旧区域宽限及在途保留） |
| `startsPerSecond` | 2 | 任意连续 20 个服务端 tick 内最多新建两个区域 |
| `loadTimeoutTicks` | 100 | 核心未就绪的超时，移除票据并释放预算 |
| `maxQueriesPerTick` | 2 | 全服每 tick 弹着点预测次数上限；每条查询仍受碰撞单元预算限制 |

多人瞄准同一中心的区域共享租期；相邻区域重叠的核心票据引用计数，FULL／依赖预算按坐标并集计算。
已经被其他玩家或模组加载的目标也使用本模组独立的票据保留，并照常计入预算，不重复创建世界区块或实体。
只添加／移除本模组自己的票据，不修改强加载列表，不强制卸载区块；其他票据保留时区块继续运行，其他票据撤销也不影响本模组的有效保留。
超出预算时不启动新区域，继续保留可正常订阅的现有实体。多人争用时可能增加响应时间。
预算限制的是本模组申请的覆盖，不是整个服务器的实际驻留区块或硬性毫秒上限；
原版卸载、其他加载器以及第三方 AI 自行访问世界产生的额外开销不由此预算控制。

AI 的寻路、捕猎、吃草等遵循各生物原本行为、周围地形、猎物及游戏规则。
活动区外的猎物可能未加载，走出核心的生物可能暂停；不无限追随它们扩大区域。
碰撞快照仍只用于远端视线／弹道，不代替真实 AI 世界，Voxy 仍为可选远景显示模组。

## 内存碰撞快照与覆盖索引

`[snapshots].enabled = true` 默认开启自然加载区块的快照采集，与弹道接管开关相互独立。
被动地形记录不受测距仪距离门槛限制：玩家平时经过的自然加载区块仍按原预算采集，供之后开镜预测与弹道使用。
它只记录已有地形，不增加加载票据、模拟区域、实体订阅或网络渲染；这些游戏功能仍要求玩家在测距仪 3 格内并符合开镜条件。
若把采集也暂停，玩家在仪器外探索的区域卸载后便无资料可用，预测会在未知区域提前结束，导致远端目标无法加载。
未曾采集、尚未采集完成或已被淘汰的区域仍是未知，弹道不会穿过；恢复采集不会凭空补齐已经卸载的缺失资料。
采集器自身不主动加载区块，也不要求安装 NeoVoxy。区域管理器恢复的真实区块同样会经过快照采集与失效流程。

每个缓存地址为 `维度 ID + 区块段 X/Y/Z`，一个区块段为 16×16×16 格。Y 是世界区块段坐标，包含负数。
覆盖索引与快照共用生命周期，提供三种状态：

| 状态 | 含义 |
|---|---|
| `UNKNOWN` | 未采集、正在采集、被修改而失效、被淘汰，或缓存已关闭 |
| `KNOWN_AIR` | 完整采集且全部等同于无水的空碰撞空间；真正全空气的区块段可走快速路径 |
| `KNOWN` | 已完成采集，包含其他碰撞／介质数据；不表示地形一定可以穿过 |

`coverage` 只查询当前内存覆盖；`find` 和 `cell` 缺失时立即返回未知／空结果，并可为磁盘索引中的已知记录安排有预算的异步读取。
查询不等待磁盘，不请求真实区块，也不安排世界采集；仅存在磁盘记录尚不足以让子弹通过。
只有完整的 4096 格采集结果能够发布。按多个 tick 分批采集时，半成品始终不在覆盖索引中。
快照有本次采集会话内递增的发布版本和采集完成时的服务器采集 tick（恢复的磁盘记录保留原值），已返回的快照对象不会被原地修改。

采集与刷新流程：

- 区块自然加载时登记坐标并安排各区块段。加载事件中不读取地形；真正采集延迟到服务器 tick，使用 `getChunkNow` 非加载查询。
- 每次只保留一个正在生成的快照。一次采集调用结束后，不在队列或半成品中保留 `LevelChunk`、`LevelChunkSection`、实体或方块实体引用。
- `LevelChunk.setBlockState` 成功修改方块后，立即使所属区块段的旧快照失效，并合并刷新请求。
  若该段正在采集，丢弃半成品后重做，避免发布修改前后混合的数据。新修改请求默认延迟 5 tick；已有待办可能更早处理。
- 区块卸载时删除其待办与半成品，保留已经完成的快照。区块再次加载时使旧快照失效，重新采集。
- 维度卸载、退出世界或停服时清理对应内存数据；完整快照可由后台保存到存档目录，正常关闭后下次按需恢复。
- 关闭缓存后查询立即返回未知，并在服务器 tick 清空数据；保留有上限的自然加载坐标索引，以便重新开启后逐步恢复。

快照以形状调色板和压缩索引保存碰撞数据，统一形状的区块段无需保存逐格索引。
自然加载的全空气或原生调色板证明为单一方块状态的区块段可直接采集，避免纯岩层逐格扫描挤占探索预算；仍受每 tick 段数和时间上限约束。
数据仅包含不可变数值，不持有 Minecraft 方块状态或世界对象：

- 支持原版非动态、无方块实体的预计算碰撞形状；半砖、楼梯、栅栏等保留实际碰撞盒。原版无碰撞方块记录为空碰撞。
- 记录是否含水，供跨卸载区域弹道近似计算水中阻力和重力。
- 未适配的模组方块、依赖实体状态的动态形状、带方块实体的形状，以及超出当前表示范围的复杂形状，记录 `CONSERVATIVE` 保守阻挡标记。
  不尝试运行它们的自定义世界查询，也不当成空气处理。
- 本模组测距仪的上下半部、四个朝向使用实际静态碰撞盒；站在仪器旁不会因保守邻域而错误阻挡视线、预测或弹道。
- 每种形状最多保存 16 个碰撞盒，坐标为方块局部坐标，允许范围为 `[-1, 2]`。
  碰撞盒可能跨出本方块（例如栅栏高于一格）；弹道追踪同时检查周围一格单元。

原版放置、破坏、流体、活塞与命令通过上述修改入口时均会触发失效。
第三方工具若绕过 `LevelChunk.setBlockState` 直接改写区块段底层容器，需要另行适配其修改通知。
缓存采集的是方块碰撞几何；TACZ 对特殊方块的额外穿透规则、命中副作用以及实体碰撞不包含在本快照层中。

资源预算均在服务端执行：

- 全服每 tick 最多采集 4096 格、完成 16 个区块段，另设 2 ms 软时间预算；全空气快速路径仍消耗一次工作额度。
  时间预算每 64 格检查一次，不能保证每个 tick 的耗时严格低于 2 ms。
- 完成的快照共享 `limits.snapshotMemoryMiB` 预算，采用 LRU 淘汰；被淘汰的段立即成为未知。
  这是对象大小的保守估算，不是 JVM 堆使用量的精确计量。队列、坐标索引和单个构建器另外受数量上限约束。
- 待办最多 8192 段，同一段的重复请求合并。队列满时暂时省略新请求，保持未知；轮询已登记区块时会重试。
- 最多登记 8192 个自然加载区块坐标，溢出时忘记最早的登记。遗漏坐标可在重新加载或正常方块修改后重新登记。
  队列补充每 tick 轮询一个已登记区块，不会为了补齐缓存加载真实区块。

## 持久化缓存与在途快照预算

`[persistence].enabled = true` 默认开启。存储目录为当前世界的 `taczlrs-collision-cache/`，不同存档自然隔离。
文件地址包含维度与区块段坐标；格式版本、碰撞分类修订或模组版本组合不匹配时放弃旧数据，不把旧注册表数字解释为新的方块。
保存的是不可变碰撞几何、介质和采集元数据，不保存历史实体，也不保存完整 Minecraft 区块。

- 启动时后台扫描有数量上限的文件索引，不批量解压碰撞数据。瞄准时可预取已知磁盘记录，缺口之外不继续探路。
- 单个后台线程处理压缩、解压及文件读写。主线程只排队和按 tick 接收不可变结果；真实世界采集仍在服务端线程执行。
- 文件包含格式标记、地址、长度和校验和，解压长度及调色板规模均有上限。缺失、截断、损坏文件只撤销对应记录。
- 区块重载或方块修改立即撤销内存与磁盘索引资格，并取消过期的排队／已完成读取；实际文件删除在后台处理。
  恢复结果发布前还检查真实区块是否已加载，当前地形优先。写队列满时也不会保留被替换的旧空气记录。
- 正常关闭时后台排空写入／失效队列，最多等待约 10 秒；只有成功完成才标记该缓存会话正常结束。
  崩溃、强制终止或关闭超时后，下次保守放弃旧磁盘缓存。索引级 I/O 故障使持久化停用，内存快照与近处射击继续工作。
- 记录正常关闭时 `level.dat` 的修改时间和大小。若存档曾在其他会话保存、关闭持久化运行，或更换模组版本，下次放弃旧缓存。
  无法识别所有离线区块编辑或保留时间戳的外部替换；做过这类修改后应在停服时删除此缓存目录。

| 配置项（`persistence`） | 默认值 | 作用 |
|---|---:|---|
| `diskMiB` | 256 | 有效文件与单个写入临时文件的内容字节预算，不含文件系统分配单元／目录开销 |
| `maxDiskSections` | 65536 | 磁盘记录／地址索引上限，另有同上限的待失效地址集合；容量不足淘汰旧记录 |
| `maxQueuedSections` | 128 | 排队、正在处理及等待主线程接收的任务数量上限 |
| `queueMiB` | 32 | 队列快照估算内存上限；每个读取预留 8 MiB，结果未消费前不释放额度 |
| `ioMiBPerSecond` | 8 | 压缩后数据读写的节流速率，允许一个有上限文件的瞬时突发 |
| `operationsPerSecond` | 128 | 后台正常读／写／删除任务速率；启动目录扫描另按索引数量限制 |
| `restoresPerTick` | 8 | 每 tick 最多接收的恢复结果数量 |
| `pinMiB` | 32 | 在途保留可使用的内存子预算，包含在 `limits.snapshotMemoryMiB` 内 |
| `maxPinnedSections` | 2048 | 全服同时保留的不同区块段上限 |

队列及完成结果共享数量／内存预算，不创建无上限 Future 队列。工作线程另有一个受 8 MiB 文件／解压长度限制的编解码任务，
其中输入、输出和临时构建对象有额外但有界的内存开销；预算是估算而非精确 JVM 堆测量。积压时省略新任务，后续查询可重试。
磁盘相关配置在下次启动时应用；保留预算可随服务端配置重载收紧。关闭持久化时仍会清理旧缓存的有效资格。

已接管子弹每 tick 预取并保留附近及接下来约两个移动步的已有快照，最多保留 256 个区块段地址的移动窗口。
多发子弹共享保留计数；普通 LRU 淘汰跳过这些段。命中、停止、超时、射手失效和维度卸载时释放保留。
保留不会阻止真实方块修改导致的失效，也不会绕过管理员收紧预算。保留名额不足时继续遵守普通缓存规则，之后遇到缺失仍截断弹道。
未准备好的磁盘快照仍为 `UNKNOWN`，不会等待磁盘后再让已经终止的子弹延迟命中。

持久化快照也可证明其所在区块曾经真实加载，使重新进入存档后仍能恢复已探索目标。
这不等于已经具备可用碰撞数据：沿途磁盘快照必须先恢复到内存并完成碰撞检查，才能授权落点；
加载邻域的每个区块也必须分别提供证据，不能仅凭落点的一个文件授权整片未知区域。
使用 `/taczlrs cache` 可查看磁盘索引、队列、损坏／省略计数及在途保留占用。

## 弹道接管与跨卸载区域射击

`[ballistics].enabled = true` 默认开启。`maxDistance = 0` 跟随 `limits.maxDistance`，默认 1024 格；
正值可单独限制弹道距离（最多 16384 格，且不超过全局上限）。距离按累计飞行路径长度计算。

原先的默认关闭开关、128 格上限，以及 TACZ 原生子弹寿命都可能造成远端无法命中。
例如当前依赖默认枪包中的 AWP 子弹寿命为 0.9 秒（18 tick），即使目标区块正常模拟，也可能在途中消失；
原生实体子弹还可能在沿途区块停止模拟时暂停。接管后子弹独立推进，不需要沿途区块进入实体更新状态。
`extendLifetime = true` 仅对成功接管的弹延长寿命，最多运行 `maxFlightTicks`（默认 600 tick，正常 20 TPS 时为 30 秒）。
枪口速度、阻力、下坠、穿透及伤害衰减保持原值；距离上限并不保证能飞到该距离，需要考虑下坠、阻挡和覆盖。
设为 `false` 可恢复原始寿命约束。未接管的子弹不修改寿命。

接管发生在原子弹完成初始化、即将加入世界时：

1. 复用附近测距仪、枪械、瞄准镜与开镜资格判定，所有倍率均可接管。
2. 仅接受标准 `EntityKineticBullet` 普通动能弹。爆炸、实体燃烧、方块燃烧及自定义子弹子类继续使用原 TACZ 路径。
3. 调度器获得子弹所有权后取消原实体生成。这份未注册到世界的 TACZ 子弹仅由调度器推进，不再由世界实体列表重复推进。
4. 如果完整扫掠包围盒及两格周边范围都已加载，继续复用 TACZ 原生 `tick()`，保留本地飞行、流体及方块命中行为。
5. 若经过卸载区域，或需要在本 tick 内截断距离，改用不调用 `Entity`／`Projectile` 基础 tick 的快照路径。
   此后该发子弹保持这条路径，避免恢复陈旧的基础实体流体／传送门状态。
   NeoForge 的 tick 前后事件仍然保留；前置事件修改后的真实位置和速度用于当次检测。

快照路径每 tick 检测本次实际位移线段，包含此前重力、阻力和开火散布形成的偏移，不依赖开镜时的一条静态直线：

- 当前区块存在时直接读取其现有区块段；当前地形优先于历史快照，且不必等待缓存重新采集。
- 当前区块已卸载时，仅使用完整快照；未采集、半成品、失效、淘汰或关闭缓存均视为未知。
- 使用逐格 DDA 与具体碰撞盒求交，检查线段周围一格，覆盖栅栏等伸出方块的形状。
  周围一格也必须已知，因此在覆盖边缘可能提前约一格停弹。`CONSERVATIVE` 单元及其邻近路径保守阻挡。
- 遇到墙体或未知数据时保留已知前缀，在首次边界前停止；不会因为远端有一个已加载目标就跳过中间缺口。
  累计距离上限在最后一段精确截断，不再整 tick 提前停弹。
- 在安全前缀内按命中距离排序真实服务端实体，复用 TACZ 碰撞盒／爆头判断、原子弹伤害与命中事件，逐次消耗原生穿透数。
  伤害事件取消仍有效，不创建历史实体或再次扣除弹药。其他玩家只要真实存在且可被服务端查询，也走同一实体路径。
- 使用原 TACZ 的“位移、阻力、重力、寿命”顺序及浮点运算精度；快照含水格按水中系数计算。
  快照没有流体高度／流向，部分浸水和流体推力并不保证与原生路径完全一致。
- 所有地形读取仅用 `getChunkNow` 或内存快照，缺失查询不排队、不读取磁盘、不请求区块票据，也不新增地形同步消息。
  短暂的区块段读取器只存在于本次计算，不会跨 tick 保持区块引用。

资源限制与生命周期：

- 每 tick 位移长度最多 256 格，DDA 最多访问 1024 个路径单元，避免异常枪包速度产生无界查询。
  超出该速度或非有限坐标会终止已接管子弹；这与可跨多个 tick 飞行的总距离上限不同。
- 默认每个维度最多接管 128 发同时飞行的子弹，允许配置 1–1024 发。容量已满时新子弹保留原 TACZ 行为；
  这些未接管子弹不受本模组距离／覆盖检查约束。
- 默认飞行硬上限为 600 tick。在测距仪范围内，收镜、切枪和关闭新接管开关不会撤销已经接管的子弹。
  离开测距仪范围、移除最后一台附近设备、射手死亡、离开世界或切换维度时清理其弹道；维度卸载、停服时释放持有的子弹。飞行状态不保存到存档。
- 如其他生成事件监听器撤销了取消标记、让原实体最终成功注册，调度器会放弃所有权并恢复其原始寿命；若第三方另行修改寿命则保留该修改，避免双重推进。
- 被接管的子弹向射手同步专用白灰尾迹；远端目标仍仅在开镜订阅规则允许时显示。
  本地原生路径保留 TACZ 方块命中反馈；快照路径撞墙只停止子弹，不调用可能读取／修改卸载地形的方块命中事件或生成弹孔。
- 快照路径使用保守碰撞几何，暂未复刻 TACZ 特殊方块穿透标签／配置和自定义方块行为；某些原生可穿过的方块可能阻挡。
  区块在卸载期间的地形仍以最后完整快照为准，重新加载后恢复当前数据优先。

开火时，接管子弹会保留射手已获批、与发射方向水平路径相交的目标区域；保留整列高度以兼容抬枪补偿下坠。
不会为在途子弹新建区域、加载走廊或绕过预算。关镜只撤销额外显示，仍在飞行的子弹可以命中被保留的真实实体。
命中终结、撞墙、未知覆盖、射程或寿命到限都会释放该发子弹的保留；多发共享区域时，其他有效保留继续生效。
这些区域一直占用全服 FULL／依赖／区域预算及每人两区域上限，不能通过连续开镜射击积累无限加载区块。
飞行超时还为保留设置兜底期限；暂停游戏不会单独消耗保留期限。
管理员关闭区域功能、变更活动配置、世界卸载等管理操作仍可主动清理区域；已走出核心的目标也不保证继续模拟。

弹道与实体筛选不主动加载沿途区块；开镜区域管理器单独负责有预算的目标加载。快照可持久化，且不依赖 NeoVoxy。
已卸载地形以历史快照为准，不能保证反映第三方绕过通知的修改；未知或被淘汰的覆盖始终截断弹道，不为补齐它临时加载区块。
原生实体伤害和 NeoForge 事件仍允许第三方回调；本扩展不替其他模组约束其任意世界访问。
快照表示服务器曾完整采集该区域，不是每名玩家各自曾看过该区域的证明；当前没有按玩家保存探索历史。

## 远端烟状弹道尾迹

仅成功接管的远距离狙击弹使用新效果，各倍率均适用；不在测距仪范围、非白名单枪械和回退至 TACZ 的子弹保持原版粒子。
接管取消了原版子弹实体生成，因此原先依赖该实体的 TACZ 粒子不会出现；新效果直接使用服务端实际飞行片段。

- 白灰色烟状尾迹、柔和透明边缘，弹头附近有更亮的小光点和淡光晕。线宽按距离与开镜投影控制，避免近处变粗或极远处缩小到不可见。不生成大颗黑烟，也不改变世界光照。
- 当前优先验证可见性：所有速度统一保留 36 tick，正常 20 TPS 时约 **1.8 秒**。
  前 4 tick（约 0.2 秒）保持基础不透明度，再平滑淡出至 0；暂不按高速子弹缩短寿命。
  用连续的程序化烟纹产生浓淡变化，取代均匀的实心中心线。旧烟逐渐变宽并轻微卷动，新烟较紧密，弹头保留亮点与淡光晕。
  表观基础半宽为 2.275–2.73 像素，烟雾的柔软外缘会随年龄有限扩散；所有变化仅影响显示。
- 使用连续渐变带和程序化烟纹表达细粒子尾迹，不逐格创建 Particle 或 Entity。保留短时间历史，能覆盖整个飞行过程，但不会同时留下从枪口到目标的永久长线。
- 每 tick 仅向射手发送已经检测过的位移片段，客户端约延迟一 tick 插值，不外推未知弹道；重力、阻力、命中和未知区域截断由服务端决定。
  原生 TACZ tick 在命中后仍可能更新位置，专用命中钩子只截取显示端点，不改变伤害和物理逻辑，避免尾迹视觉上穿墙。
- 独立绘制不依赖客户端区块或原版粒子更新，不发送地形、不请求区块。保留深度测试，因此现有地形会遮挡后面的尾迹。
  Voxy 仍是可选项；特定远景／光影组合的深度缓冲效果需要在对应环境中验证。
- 在测距仪旁收镜后已发射子弹的尾迹继续显示并淡出；离开／拆除测距仪、切换世界／维度和断开连接会清空历史。即使丢失最后一次更新，也会按短寿命清理残影。
- 每名射手每 tick 最多一个批次、128 个片段；客户端最多缓存 128 发、每发 40 个片段（涵盖 1.8 秒尾迹及插值余量），单帧线段细分也有上限。
  单发持续飞行约产生 1–2 KB/s 的载荷及消息头开销，不向所有玩家广播；预算不足只省略显示，不影响命中或加载预算。

弹道同步要求客户端和服务端使用兼容版本；烟状效果复用原有轨迹消息，不增加同步频率或区块加载。
专用客户端着色器生成平滑烟纹，沿路径使用连续坐标，避免消息接缝及逐帧随机闪烁；随资源重载重新加载。当前效果参数采用上述固定默认值。

## 调试与接口边界

- 管理员执行 `/taczlrs cache`（权限等级 2），查看全服快照数量、待办、估算内存、淘汰／丢弃请求次数及上一 tick 工作量，
  同时查看执行位置所在区块段的覆盖状态、版本和保守阻挡格数。命令本身不会触发采集或区块加载。
- 游戏内执行 `/taczlrs status`，查看自己的枪械、瞄准镜、当前档位、倍率及拒绝原因，无需 OP。
  同时显示弹道开关、距离上限、当前维度的活动／累计接管／未知区域终止／距离终止计数，
  以及延长寿命开关、飞行时间上限、寿命／超时终止、快照阻挡、最后终止原因与最后接管结果。活动区域状态包含在途保留数（按区域分别计数）。
  也显示开镜实体订阅开关、数量上限、当前订阅数和刷新间隔。
- 开启 `diagnostics.enabled` 后，服务端日志在资格变化时输出状态，在合规子弹生成时输出参数与接管结果，并记录弹道终止原因。
  订阅集合变化也会记录。输入聊天命令通常会收镜，观察真实开镜与变倍状态时应使用这个日志开关。
- `TaczBridge.evaluate` 在调用时重新读取装备和状态；服务端使用射手即时开镜状态，避免同步标记延迟。
- `TaczBridge.inspectNewBullet` 在 TACZ 初始化子弹之后读取实际位置、速度、寿命、重力、阻力、穿透数、有效射程、爆头倍率、穿甲比例及爆炸／燃烧标记。
  有效射程是 TACZ 的伤害参数，不等于子弹最大飞行距离。接管时只按配置延长寿命，不重新计算伤害衰减等参数。
- `TaczShotObservedEvent` 是服务端的不可取消观察事件，包含原始子弹和不可变的开火时快照，在弹道接管判定前发布。
  已加载存档实体、客户端实体、不合规装备以及枪械 ID 不匹配的子弹不会发布此事件。
- 私有参数通过 Mixin Accessor 获取；快照路径另外使用原生实体命中 Invoker，并递减子弹剩余穿透数。
  接口按固定的 TACZ `1.1.8-hotfix-r6` 验证；升级 TACZ 后需重新运行测试。

并直接读取依赖 JAR 核对默认枪械类别和瞄准镜引用的真实倍率表。

未知中间区块不加载、距离与容量限制、特殊弹药回退、伤害事件取消、实际生成事件接管、唯一推进及生命周期清理。
测试中部分寿命／重力／阻力／穿透／特殊弹药字段由测试夹具设定，以隔离验证对应行为，生产代码按 `gunOverrides` 覆盖发射参数，并对成功接管的子弹按配置延长寿命。
第三步增加快照发布原子性、修改期间重建、负坐标／维度隔离、预算／淘汰、真实半砖／楼梯／栅栏形状、
修改 Mixin、无副作用查询及自然卸载后仍可查询快照的测试。
第四步增加已知／未知路径、负坐标和边界、斜线、细小与跨格形状、重力偏移、异常输入、精确距离截断，
以及快照路径与原生身体／头部伤害、穿透事件的对照测试。
实际服务端测试先采集一段走廊、等待中间三个区块自然卸载，再只开放首尾区块，验证远端命中、缓存墙体、
多 tick 飞行、伤害取消、当前地形优先、覆盖失效后截断，以及射击没有增加已加载区块或请求采集。
测试类和测试结构位于独立 `gameTest` 源集，不进入发布 JAR。
开镜功能验证实体类型不再受类别筛选、全倍率授权、原版观察者交接、墙体／未知区域／读取预算及网络消息边界。
视野缓冲测试覆盖不同窗口比例、内外边界保留、中央目标优先、数量上限、保留期间墙体遮挡，以及视野提示的装备／维度验证、限频和角度上限。
远端模拟测试验证存档生物卸载后恢复、真实寻路与狼攻击猎物、敌对生物距离消失豁免、FULL 预算拒绝、多人共享区域与分别收镜、实际卸载。
回归场景先在没有测距仪时通过生产 tick 入口采集自然加载地形，再等待目标实体和途中区块真实卸载，最后部署测距仪开镜恢复目标 AI、订阅与远端命中。
采集期间另行验证：没有测距仪的玩家即使瞄准也不会获得额外实体订阅或远端模拟区域。
新增测试验证短寿命弹延寿后的射程／时间硬上限、原生所有权恢复时还原寿命，以及真实远端目标区块在收镜超过宽限后仍被在途子弹保留并命中。
同一场景验证中间区块保持卸载、独立第三方票据的双向撤销互不影响、在预先加载的区域重新开镜不会重建实体。

同时检查位于镜片内但超过旧准星锥体的 224 格外目标实际补绘；再通过真实子弹及网络消息验证 160 格外且无客户端地形的尾迹绘制、收镜继续显示与自动消散；
保存 `screenshots/scope-render.png`、`screenshots/shot-trail.png`，成功后自动退出；测试过程自身会准备地形与目标，这不是生产订阅逻辑的区块加载行为。

## 开镜直线测距

在附近测距仪旁使用合规枪械和瞄准镜开镜后，各倍率均计算直线测距；圆筒光学视图左下方显示绿色七段数码读数，例如 `238.0 blocks`，保留一位小数。
定位沿用通用镜片几何投影，无须为每个倍率硬编码坐标；TACZ `views=2` 的光学视图显示，`views=1` 的备用机械／开放式视图隐藏。
例如 MK5HD 的 5×／25× 与 LPVO 的 1.25× 均显示，MK5HD 的 1.25× 备用瞄具不显示，但仍处理测距和远端弹道。
数字位于实际镜片网格投影边界内，同时受 TACZ 圆形视野遮罩范围约束；离开／拆除测距仪、镜头尚未完全举起、收镜、
第三人称、隐藏 HUD 或打开菜单时不绘制。读取镜片已经输出的顶点，不进行 GPU 像素回读，也不改写原有顶点、属性或模板缓冲。

测量的是玩家眼部到准星中心直线首次命中碰撞表面的欧氏距离：先遇到实体就报告实体表面距离，先遇到方块就报告方块表面距离。
这不是实体中心距离，不计算下坠，不受子弹寿命影响，也不会把预测弹着点作为测距目标。
使用服务端当前地形／碰撞快照与已有可见实体；不创建加载票据、不主动读取实体存档，也不把 Voxy LOD 当作精确地形。
碰撞快照不是完整方块轮廓：没有碰撞体积的装饰植物等不会成为测距阻挡，缓存地形也可能不是最新状态。
空气、未知区域、无法确定真实表面的保守碰撞形状、超出 `limits.maxDistance`、读取／时间预算耗尽时显示 `--- blocks`，不会伪造最大距离或将保守阻挡位置显示成精确距离。

刷新复用 `scopeRendering.intervalTicks`，默认每 4 tick 一次（20 TPS 下约 5 次/秒）。全服额外最多 2 条测距线/tick，
共享 2 毫秒/tick 的软预算，每条查询仍受碰撞单元数与实体检查次数限制。沿用订阅候选列表，不另扫描全世界实体。
每次仅向对应玩家发送一个距离及采样视线，默认每位开镜玩家的测距载荷约数百字节/秒，不增加整区块或实体同步。
客户端转向／移动后，旧视线不再匹配或超过 10 tick 未更新时会显示未知，等待新采样，避免把旧目标距离套到新目标上。
客户端与服务器需要同时更新（网络协议版本 5）。

测距测试覆盖最近方块／实体、遮挡、未知区域、空气及资源预算；真实客户端验证 238 blocks 的远端读数，
检查镜片左下区域确实出现绿色像素，并确认收镜后停止绘制。
新增测试检查 3 格精确边界、上下半部与欧氏距离、同 tick 移动／拆除、多个测距仪、全部变倍档位的子弹接管、
离开／拆除设备后的在途弹道终止，以及多玩家共享区域的分别撤销。
客户端额外验证 MK5HD 5×、LPVO 1.25× 的读数，备用机械瞄具隐藏 HUD，以及移除设备后停止功能。


## 测距仪方块

新增 `tacz_long_range_sniping:rangefinder`，中文名“测距仪”，位于 TACZ 枪械工作台所在的创造模式物品栏。
放置后为附近 3 格的玩家启用本扩展；仪器方向不限制有效范围，多个玩家可以共享。
测距仪只提供启用条件，不发射测距射线，也不提供测距起点、方向或读数；直线测距始终使用玩家眼部位置和瞄准方向。
它仍是有碰撞的普通方块：真正瞄准仪器实体部分时可以命中；射线经过其旁边或三脚架空隙时不会被虚构的整格／邻域形状阻挡。
屏幕与按钮仍属于静态装饰，没有右键界面，实际测距读数显示在玩家瞄具内。

方块上下占两格，支持四个水平朝向；放置时仪器前面朝向玩家。三根倾斜长方体组成黑色三脚架，顶部包括黑色仪器箱、
突出物镜、辅助窗口、背面目镜、小屏幕、按键和侧面调节块。使用一个 64×64 像素贴图和普通 JSON 方块／物品模型，
没有方块实体、逐 tick 更新或专用方块渲染器。模型及贴图可由 `tools/generate_rangefinder_model.py` 再生成。

需要坚实的底部支撑和连续两格可放置空间。拆除上半部、下半部或移除支撑时会清除整机；生存模式只掉落一个物品，
创造模式不掉落。上下半部共用朝向，只有下半部拥有掉落表，活塞不能将两半分别推走。
破坏音效使用铁砧音效，粒子使用铁砧纹理；放置等其他音效保留原来的工作台木质音效；硬度 2、爆炸抗性 3，斧为有效工具。

合成产出一个测距仪：

```text
ABA
XCX
CXC
```

X 为空位；A 为无色玻璃板，B 为钻石，C 为铁锭；共消耗 2 个无色玻璃板、1 个钻石和 3 个铁锭。
获得钻石后解锁配方书条目。

服务端测试验证实际物品放置、四向状态、上下半部拆除、移除支撑、创造模式拆除、不足两格时拒绝放置、
配方与音效；客户端验证世界／物品模型无缺失贴图、创造模式栏归属，并保存 `rangefinder-block.png` 和 `rangefinder-front.png`。

全局物理回归覆盖默认六枪的生产散布派发入口、TACZ 专用散布入口、远离测距仪／收镜／所有倍率、未覆盖参数回退、原生子弹生成消息往返同步，以及预测曲线上的实际原生／接管伤害。
